Building an AI Decision Flow with React Flow & Inngest

A master guide detailing how to build a durable, interactive AI workflow system where every decision node queries an LLM for strict YES / NO branching executed via Inngest step runners and rendered in real time.

Next.js 16 (App Router) @xyflow/react (React Flow v12) Inngest Durable Execution OpenAI SDK (gpt-4o-mini) Tailwind CSS
Implementation Steps 0 / 8 Done
💡 Inngest Pro Tip

By wrapping each node in step.run(nodeId), Inngest automatically guarantees step-level retries, checkpointing, and real-time visualization in the Inngest Dev Server dashboard.

00

The Core Mental Model

Traditional workflows use rigid code branching (if / else). In contrast, an AI Decision Flow lets non-engineers or product teams define natural language queries (e.g. "Is this customer requesting a refund?") inside visual graph nodes.

Type Definitions & Graph Schema

Create src/types/flow.ts to define the typed contract for nodes, edges, decisions, and execution telemetry:

src/types/flow.ts 
import { type Node, type Edge } from '@xyflow/react';

export type NodeExecutionStatus =
  | 'idle'
  | 'pending'
  | 'running'
  | 'passed-yes'
  | 'passed-no'
  | 'completed'
  | 'skipped'
  | 'failed';

export interface DecisionNodeData {
  label: string;
  prompt: string;
  category?: string;
  executionStatus?: NodeExecutionStatus;
  lastDecision?: 'YES' | 'NO';
  lastReason?: string;
  durationMs?: number;
}

export interface ActionNodeData {
  label: string;
  actionType: string;
  executionStatus?: NodeExecutionStatus;
}

export type CustomNodeType = 'start' | 'decision' | 'action';

export type FlowNode = Node<DecisionNodeData | ActionNodeData, CustomNodeType>;

export interface DecisionEdgeData {
  condition: 'YES' | 'NO';
  isActive?: boolean;
}

export type FlowEdge = Edge<DecisionEdgeData>;

export interface ExecutionStepLog {
  stepIndex: number;
  nodeId: string;
  nodeLabel: string;
  nodeType: CustomNodeType;
  prompt?: string;
  decision?: 'YES' | 'NO' | 'ACTION';
  reason?: string;
  durationMs: number;
  timestamp: string;
}

The Binary LLM Decision Engine

The heart of the workflow is src/lib/llm.ts. It takes a decision node's prompt and the customer input context, enforcing a strict binary output contract (YES or NO) plus a one-sentence rationale:

src/lib/llm.ts (Excerpt) 
const response = await client.chat.completions.create({
  model: 'gpt-4o-mini',
  temperature: 0.1,
  messages: [
    {
      role: 'system',
      content: `You are an AI decision engine in an automated workflow.
Evaluate the Decision Question against the provided Input Context.
You MUST answer with EXACTLY ONE binary decision: YES or NO.

Format strictly as:
DECISION: [YES or NO]
REASON: [One clear sentence explaining why]`
    },
    {
      role: 'user',
      content: `Decision Question: ${prompt}\n\nInput Context:\n"""\n${inputText}\n"""`
    }
  ]
});

04

Dynamic Graph Traversal Engine

Create src/lib/workflow-engine.ts to traverse graph nodes dynamically. When a decision node returns YES, the engine inspects outgoing edges from handle yes; when NO, it takes handle no:

Branching Logic Excerpt 
// Find edge matching chosen decision
const chosenDecision = stepLog.decision; // 'YES' or 'NO'
const outgoingEdges = edges.filter(e => e.source === node.id);

let nextEdge = outgoingEdges.find(e => {
  const handle = (e.sourceHandle || '').toLowerCase();
  const cond = (e.data?.condition || '').toUpperCase();
  return chosenDecision === 'YES' 
    ? (handle === 'yes' || cond === 'YES')
    : (handle === 'no' || cond === 'NO');
});

currentNode = nodeMap.get(nextEdge.target);
05

Inngest Durable Steps Integration

Configure Inngest to orchestrate each node as a separate, durable, retryable step:

src/inngest/functions.ts 
import { inngest } from './client';
import { executeWorkflowCore } from '@/lib/workflow-engine';

export const executeWorkflowFunction = inngest.createFunction(
  {
    id: 'execute-ai-decision-flow',
    name: 'Execute AI Decision Workflow',
    retries: 2,
    triggers: [{ event: 'flow/workflow.execute' }],
  },
  async ({ event, step }) => {
    return await executeWorkflowCore({
      nodes: event.data.nodes,
      edges: event.data.edges,
      inputText: event.data.inputContext.text,
      stepRunner: async (stepId, fn) => {
        // Wrap each node in an Inngest step!
        return await step.run(stepId, fn);
      },
    });
  }
);

Mount the Inngest serve handler in src/app/api/inngest/route.ts:

src/app/api/inngest/route.ts 
import { serve } from 'inngest/next';
import { inngest } from '@/inngest/client';
import { inngestFunctions } from '@/inngest/functions';

export const { GET, POST, PUT } = serve({
  client: inngest,
  functions: inngestFunctions,
});
